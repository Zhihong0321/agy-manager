agy-web API

Run the Antigravity CLI (agy) in the cloud as an HTTP API, across a pool of Google accounts with quota-aware failover. Base URL for this deployment: …

Auth: every /api/* route requires Authorization: Bearer $AGY_WEB_TOKEN (the service's token). Without it you get 401. /healthz and this page are the only open routes. POST /api/prompt runs real tools on the server — treat the token like a root password.

Quickstart

LAB=$(location.origin)   # e.g. https://agy.up.railway.app
TOK=<your AGY_WEB_TOKEN>

# 1. is it up / who is active?
curl -s -H "Authorization: Bearer $TOK" "$LAB/api/status"

# 2. run a prompt headlessly (tools auto-approved by default)
curl -s -X POST -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' \
     -d '{"prompt":"Reply with exactly: OK"}' "$LAB/api/prompt"

# 3. run a prompt that USES TOOLS against a workspace on the volume
curl -s -X POST -H "Authorization: Bearer $TOK" -H 'Content-Type: application/json' \
     -d '{"prompt":"List the files in the cwd and count them","cwd":"/data/work","sandbox":true,"timeout":300}' \
     "$LAB/api/prompt"

POST /api/prompt — the headless agy runner

Runs agy -p <prompt> as one account and returns the answer. Synchronous; bounded by timeout.

FieldTypeDefaultMeaning
promptstringrequiredThe instruction for agy.
accountstringactivePool account to run as. Omit for the active one.
toolsboolserver default (true)Auto-approve tools (--dangerously-skip-permissions). Set false to disable.
sandboxboolserver default (false)Add --sandbox to restrict what auto-approved tools may touch.
cwdstringaccount homeWorkspace directory for the run. HOME still selects the account.
modelstringagy default--model override.
timeoutint (s)180Per-run limit; the call returns an error if exceeded.

Response:

{ "ok": true,  "account": "you@gmail.com", "cwd": "/data/...", "ms": 13615, "exit": 0, "answer": "…" }
{ "ok": false, "account": "…", "ms": …, "exit": …, "auth_failure": bool, "error": "…" }
Why tools auto-approve by default: a remote/print agy blocks on tool-permission prompts that nobody can answer, and agy has no per-tool allow flag — auto-approval is all-or-nothing. The server therefore defaults it ON (AGY_AUTO_APPROVE) so headless calls actually complete; override per request with tools:false, or narrow with sandbox:true.
cwd caveat: a directory agy has never trusted can trigger a folder-trust prompt that headless cannot answer (the run then ends at timeout). Prefer dirs agy already trusts, or pre-trust them.

Examples in other languages

// JavaScript / fetch
const r = await fetch(LAB + "/api/prompt", {
  method: "POST",
  headers: { "Authorization": "Bearer " + TOK, "Content-Type": "application/json" },
  body: JSON.stringify({ prompt: "Summarise the cwd in 3 bullets", sandbox: true })
});
const { ok, answer, error } = await r.json();
# Python / requests
import requests
r = requests.post(f"{LAB}/api/prompt",
    headers={"Authorization": f"Bearer {TOK}"},
    json={"prompt": "Reply with exactly: OK", "timeout": 120}, timeout=140)
print(r.json())

Accounts & status

MethodRoutePurpose
GET/api/statusActive account, switch mode/policy/runtime, log-watch, and every account's state (enabled, status, health, short/weekly quota %, reset, identity, proxy, last check).
GET/api/verifyVerify saved accounts' auth/runtime usability.
GET/api/models?name=agy models for the active or a named account.
POST/api/switch {name}Make an account active (instant file swap).
POST/api/switch-nextRotate to the next eligible account (skips cooldowns).
POST/api/ensure-active {force?}Preflight/recover a usable active account per policy.
POST/api/rotate {reason, cooldown_minutes, force_switch}Fail over now: mark active bad, switch to a standby.
POST/api/accounts/{name}/enable {enabled}Enable / disable an account.
POST/api/accounts/{name}/mark-bad {reason, cooldown_minutes}Mark bad + cooldown.
POST/api/accounts/{name}/clear-badClear bad/cooldown.
POST/api/accounts/{name}/refresh-usageLive quota refresh (runs agy / Code Assist).
DEL/api/accounts/{name}Remove the account and its saved profile.
POST/api/import-current {name, source?}Seed an account from an existing .gemini home.
GET/POST/api/switch-policyRead/set short-usage threshold, refresh-failure threshold, candidate strategy.
POST/api/switch-mode {mode: auto|manual}Whether failures auto-fail-over or just mark bad.

Enrolling accounts (interactive login)

Starts a headless agy OAuth login in a pty and streams it. Open the printed URL, consent, then paste the code.

MethodRoutePurpose
POST/api/login {name}Start; returns a session id.
GET/api/login/{sid}?offset=NStream output from a byte offset (poll ~1s).
POST/api/login/{sid}/input {text}Paste the OAuth code / answer a prompt.
POST/api/login/{sid}/killEnd the session.
agy only waits ~60s for the code. Be signed into the Google account in another tab first so consent is fast; on timeout just start again. On success the profile is captured automatically and appears in /api/status.

Debug

GET/api/debugServer/platform env, agy + script availability, login sessions with capture results.
GET/api/debug/pty/{sid}Raw vs ANSI-cleaned pty buffer for a login session.

Errors

StatusMeaning
401Missing/bad bearer token.
400Bad request or a manager error (e.g. unknown account, empty prompt, no active account).
404Unknown route / session / account.
200 + ok:falseThe call ran but agy failed; read error. auth_failure:true means re-login or switch account.

Automation recipe (bots / schedulers)

1. GET  /api/status                 # read active + switch_mode/policy
2. POST /api/ensure-active          # preflight before real work
3. POST /api/prompt {…}             # do the work
4. on auth/quota failure:
     POST /api/rotate {reason:"quota", cooldown_minutes:60}
     retry the prompt once on the new active account
5. optionally POST /api/accounts/{name}/refresh-usage to keep quota fresh

Consumer Google accounts driven headless from a datacenter IP are the pattern that gets accounts flagged; per-account proxies are supported by the underlying manager. Keep AGY_WEB_TOKEN secret — /api/prompt with tools is remote code execution on this host.
